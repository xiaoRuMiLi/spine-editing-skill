# Spine 踩坑清单（本项目的硬规则）

> 这份不是教程，是**已经踩过的坑**。每条都写成「现象 → 根因 → 规则 → 谁在守」，
> 守 = 有测试或断言盯着，下次犯同样的错会直接报错，而不是等你在一张截图里发现。
>
> 校验命令：`python -m spine_forge.cli check <skeleton.json>`（`assemble` 结束时也会自动跑一遍）。

## 一、权重（weights）

### 1. 权重是什么

Spine 的**蒙皮网格（mesh 附件）**里，每个顶点不是死绑一根骨，而是记着「**受哪几根骨影响、各占多少**」：

```
顶点 = 骨数量 n，然后 n 组 (骨索引, 该骨局部系下的 x, y, 权重)
权重：0~1，同一个顶点的所有权重加起来必须 = 1
```

- 1 根骨、权重 1.0 → 刚性（整块贴图跟着一根骨转，不会变形）
- 2 根骨、0.5/0.5 → 顶点停在两根骨形变的**中间**，这就是"关节处平滑弯"的来源
- 权重 0 就是没影响；**权重不归一**（和为 0.7）顶点会"缩"向原点/另一根骨

Spine 编辑器里叫 **Weights / Bind（绑定）**：在 Mesh 模式下用画笔给顶点刷权重，
或者用 `Auto` 按骨骼链自动分配。这个项目是**算出来的**，不是手刷的。

| 顶点受几根骨 | 效果 |
|---|---|
| 1 | 刚体，不动形 |
| 2 | 一个关节能弯（膝、肘） |
| 3~4 | 可弯成弧线（一根肢体多节骨） |
| >4 | Spine 上限是 4，多了会被丢/报错 |

### 2. 【坑】权重不能按"单根骨轴线投影"分配

- **现象**：拖膝盖/抬脚时，大腿上半被拽走，出现一块苍白的弯月，看着像膝盖脱节。
- **根因**：贴图框的左上角离膝盖 80px，但它在**小腿轴线上的投影**只有 -7.7px，正好落进
  ±10px 的过渡带 → 这块大腿被分给了 `shin_*`。
- **规则**：权重按「顶点到**整条骨链**（髂→膝→踝）的最近点」的**弧长**分配，不是单根骨的投影。
- **谁在守**：`tests/test_assemble_warp.py::test_nothing_above_the_knee_is_weighted_to_the_shin`
  （断言腿的**顶行顶点只绑大腿骨**；旧算法下这条必挂）。

### 3. 【坑】权重顶点格式不是 x,y 对

- **现象**：顶点全挤在一起，或者人形整个消失。
- **规则**：`boneCount` + `boneCount × (boneIndex, x, y, weight)`；x/y 是**同一个世界点在各自骨
  局部坐标系**里的坐标（同一顶点对两根骨有两组不同的 x/y，这是正常的）。
- **谁在守**：`core/verify.py`（骨索引越界、权重和≠1、顶点数=uvs/2）+ `rig/mesh.py` 生成后自检。

## 二、UV

### 4. 【坑】mesh 的 uvs 是"图内 0..1"，不是图集绝对坐标

- **现象**：腿渲染成一块纯色矩形（因为所有 uv 被压缩到纹理的一个小角落）。
- **根因**：运行时用 region 的 bounds 再换算一次：`texUV = region.u + uv * region.width`。
  写成绝对坐标就等于被缩放了两遍。
- **规则**：`uvs` 是图内 0..1；**只有 region 附件**的 bounds 才是图集坐标。
- **谁在守**：`core/verify.py`（uv 超出 0..1，或 0..1 内只覆盖 <0.25 的一小片 → 报错）。

### 5. 【坑】mesh 的 v 轴：0 在**上沿**

- **现象**：贴图在网格里上下镜像。
- **规则**：图集 y 向下，`v=0` 对应图的**上边**（region 附件的 BL 顶点拿到的才是 `v2`）。
- **谁在守**：`tests/test_rig_mesh.py::test_uv_v_runs_down_the_image_like_the_atlas_does`。

### 6. 【坑】hull 必须先写、且沿轮廓顺序

- **现象**：编辑器里网格轮廓乱成一团，或点不进 Mesh 编辑模式。
- **规则**：顶点数组**前 `hull` 个**是外轮廓（顺时针/逆时针绕一圈，自己闭合），其余才是内部顶点；
  `hull` 是数量不是索引。`edges` 可选（本工具写轮廓环）。
- **谁在守**：`tests/test_rig_mesh.py::test_hull_vertices_are_walked_around_the_outline`、
  `test_edges_close_the_hull_loop`。

## 三、骨骼与约束

### 7. 【坑】刚性图片不可能形变

- **现象**：拖脚时骨在动、画不动；或者切开的两块在关节处裂开 V 形口子。
- **规则**：要么用 mesh 蒙皮（首选），要么切开分别绑骨（会撕裂、不推荐）。
- **谁在守**：`tests/test_assemble_warp.py::test_each_leg_is_one_mesh_instead_of_two_halves`。

### 8. 【坑】IK 的 `bendPositive` 决定膝盖朝哪边翻

- **现象**：拖脚时膝盖翻到"反关节"的另一侧，看着像脱臼。
- **规则**：`bendPositive=true` ⇔ 关节**落在"根骨→目标"这条线的右侧**（y-up、顺时针）。
  运行时是 `a2 = acos(cos) * bendDir`，符号反过来就是镜像解。
  推导依据：spine-player 的 `IkConstraint.apply2`。
- **谁在守**：`rig/constraints.py::bend_sign` + 静止姿势逐像素比对（错了膝盖会偏 ~75px）。

### 9. 【坑】拖"膝盖骨"没用——IK 每帧会覆盖旋转

- **现象**：在编辑器里抓小腿骨（膝点）拖动，图不跟着走 → 像脱节。
- **规则**：IK 链上的骨，**只能拖目标骨**（本项目是 `ik_foot_r/l`、`ik_hand_r/l`）。
  要"拖膝盖也灵"，就得放弃 IK 或用路径约束，二者不能同管一批骨。

### 10. 【坑】约束之间抢同一批骨，**数组顺序决定谁赢**

- **现象**：加了 path 约束后 IK 失效（或反过来），且不报错。
- **规则**：`constraints` 按数组顺序依次 apply，后面的覆盖前面的；同一批骨只能有一个"老板"。

### 11. 坐标系：y 只翻一次

- **规则**：部件/关节用图像像素（y 向下）；Spine 世界是 y 向上。只在求世界坐标时翻一次，
  附件 `rotation = -骨世界角`，偏移用反旋后的局部坐标。
- **谁在守**：`tests/test_rig_mesh.py::test_rest_pose_reproduces_the_source_pixels`
  （静止姿势能逐点反算回原图像素，误差 1e-3）。

## 四、怎么验证一张图"对不对"

1. **静止姿势必须先逐像素对上**（和已验收的旧版本比平均差；本项目 0.031 = 只有边缘抗锯齿）。
   摆位错了就说明坐标/uv 错了，别急着看动画。
2. **再摆极端姿势**：本项目用「A 拖膝盖 / B 抬脚踝 / C 拖出可达范围」三种拖法各出一张图。
3. **必须用官方 runtime 渲染**（spine-player），不能用自己画的近似 —— 本项目的坑全是"本地看着对、
   官方不对"。
4. 生成后先跑 `spine_forge.cli check`，结构错了当场报，不用等截图。

```bash
python -m spine_forge.cli assemble examples/girl/parts.json \
  --bones examples/girl/rig/bones.json --out examples/girl/dist-warp \
  --name girl --mode atlas --warp legs      # 结束时自动 check
```
