# 平涂插画拆分流程（parts-splitting）

> 一张平涂插画 → 11 个命名部件 PNG（全画布对齐）→ 供下一步摆骨点用。
> 本文档同时是**操作手册**和**坑点档案**：每一条算法规则都是从一次真实失败里长出来的，
> 后面改代码的人请先读「坑点」一节再动手。

---

## 一、一句话流程

```bash
spine-forge split <图片> --out <输出目录> --splitter colour
```

产物：

```
<输出目录>/
├── parts/
│   ├── shirt.png  hair.png  head.png  shorts.png
│   ├── leg-left.png  leg-right.png  arm-left.png  arm-right.png
│   ├── foot-left.png  foot-right.png  accent.png
│   └── parts.json                 # 每个部件的 bbox / 中心点 / 像素数
└── preview/
    ├── parts_sheet.png            # 部件拼版（人工验收用）
    └── reassembly.png             # 原图 | 重组图（左右对照）
```

- 每张 PNG 都是**原始画布尺寸**、只在该部件范围内有不透明像素。不裁切。
- `split --splitter alpha`（默认）走的是另一条线：给"已经按透明度分好层"的素材用。

## 二、算法四步

### 1. 找"填色"，不是找"像素色"

- 在 16 级 RGB 直方图上取**峰值**（覆盖面积 ≥ 前景的 0.08%，且 ≥40px）。
- 峰值之间做**合并**：Lab **色度**距离 ≤ 8、**明度**差 ≤ 22 视为同一填色。
  笔触阴影会让同一个填色明度漂移很多、色相少动 —— 所以明度放行、色度收紧。
- 每个像素归到最近的调色板项，距离度量 = `Δa² + Δb² + (0.45·ΔL)²`；
  超过 `MAX_FILL_DISTANCE=20` 的**不归任何填色**（水印、扫描阴影就靠这条出局）。

### 2. 给每个填色命名（色族窗口）

`hue` + `sat` + `val` 三条界，**顺序敏感**（先匹配先赢）：

| 顺序 | 族 | 色相 | 附加条件 | 为什么 |
|---|---|---|---|---|
| 1 | `orange`（裸露手臂） | 12–50 | sat ≥ 0.66, val ≥ 0.78 | 和棕色袖子同色相，只能靠饱和/亮度分开 |
| 2 | `shirt`（棕色衣物） | 12–50 | sat ≥ 0.28 | |
| 3 | `hair`（绿发） | 100–158 | sat ≥ 0.30 | |
| 4 | `shorts`（浅绿短裤） | 55–100 | sat ≥ 0.20, val ≥ 0.62 | 明度下限挡住衬衫的橄榄色阴影 |
| 5 | `teal`（凉鞋） | 160–205 | sat ≥ 0.25 | |
| 6 | `blue`（袜子） | 205–245 | sat ≥ 0.25 | |
| 7 | `purple`（眼睛/嘴） | 265–330 | sat ≥ 0.25 | |
| 8 | `skin`（皮肤/红） | 330–15（跨红） | sat ≥ 0.30 | |

没被任何族认领的像素先留空，后面交给邻域多数或丢弃。

### 3. 连通域 → 部件

- 行游程 + 并查集，**8 连通**（斜向抗锯齿边不该把部件切开）。
- 同一个族里，**盒子间距 ≤ 12px** 的碎片合并成一件（凉鞋带切开袜子就是这种情况）。
- 面积 < 前景 0.02% 的分量当噪点。

### 4. 清理与命名

清理（顺序不能乱）：

1. **邻域多数投票**（半径 1，≥3 票）：抗锯齿的混色像素还给真正相邻的填色。
2. **灰线生长**：仍无归属的前景像素，按 3×3 窗口里最多的族认领（6 轮）。
3. **小色块兜底**：直方图里低于阈值的孤岛（眼睛、嘴唇）用自身均色再判一次族，
   否则会被周边肤色吞掉。
4. **孤儿吸收**：小岛被大件包住（≥75% 边界）且色度接近 → 算它的阴影；
   细长笔画（<400px 且面积/外框>0.40 判非细长）→ 丢弃。
5. **描边剔除**：开运算(半径 3) 定"身体"，离身体 >3px 且
   （贴着别的部件 **或** 比本体暗 15 个 L）的像素判为描边，**直接丢弃**。
6. **孤岛剪枝**：每件只保留主体 + "与主体距离 ≤3px 或面积 ≥5%" 的岛。

命名：

- **左右 = 角色自身的左右**。画面朝向观众，所以**观众左手边 = 角色右手**。
- 分界线用**角色重心线**（按面积加权 cx），不是画布中线。
- 分带：`cy < 0.30H` → head；`0.30–0.62H` → arm；`≥0.62H` → leg。
- 袜 + 鞋按同侧合并为 `foot-left` / `foot-right`（视觉一体、动作同步）。

## 三、可调常量（`src/spine_forge/splitter/colors.py` 顶部）

| 常量 | 默认 | 作用 | 调大会怎样 |
|---|---|---|---|
| `BG_VALUE` / `BG_SATURATION` | 0.90 / 0.12 | 纸张背景判定 | 调大 → 吃掉浅色高光 |
| `MIN_AREA_RATIO` | 0.0002 | 分量最小面积 | 调大 → 小部件（眼睛）消失 |
| `MERGE_GAP` | 12 | 同族碎片合并间距 | 调大 → 两只鞋粘成一只 |
| `ABSORB_AREA_RATIO` | 0.05 | 孤儿吸收面积上限 | 调大 → 吞掉真部件 |
| `ENCLOSED_RATIO` | 0.75 | 判定"被包住"的边界比例 | 调小 → 吞掉边缘部件 |
| `STROKE_AREA` | 1200 | 笔画判定面积 | 调大 → 丢真实细节 |
| `GROW_ROUNDS` | 6 | 灰线生长轮数 | 过大 → 串色 |
| `MERGE_CHROMA` | 14 | 同色判定（Lab 色度） | 调大 → 肤色和衬衫混 |
| `MAX_FILL_DISTANCE` | 20 | 调色板最大距离 | 调大 → 水印混进来 |
| 描边开运算半径 | 3（代码内） | 越界描边剔除 | 见坑点 4 |

## 四、坑点档案（重点）

### 坑 1：用 k-means 找填色 —— 大片被切碎、小色块被吞

**现象**：绿头发和浅绿短裤并成一块；青色凉鞋整块消失；测试图里两只鞋变成一只。
**根因**：k-means 按"点云距离"分簇，纯色大块会被拆成几簇，而面积小的填色
（鞋 1.5%）抢不到簇心。
**修法**：改成**直方图峰值 + 色度合并**。填色本来就是"一大片同一个 RGB"，峰值才是真调色板。
**别再犯**：不要再"加点 k"试图救它 —— k=14/k=16 都一样翻车。

### 坑 2：只按色相分族 —— 棕色衬衫 vs 裸露手臂

**现象**：手臂被判成衬衫，衬衫阴影被判成手臂。
**根因**：两者色相几乎一致（≈27°），差别在**饱和度与亮度**。
**修法**：族规则带 `min_sat` / `min_val`，且 `orange` 必须排在 `shirt` **之前**。

### 坑 3：绿头发 vs 浅绿短裤：明度不同、色度相似

**现象**：短裤被并进头发族；或反过来，头发被判成短裤。
**根因**：两者 Lab 色度只差 ~10，**明度差 30+**。
**修法**：`shorts` 加 `val ≥ 0.62`；**不要**按"色度接近就合并"来分族
（试过一次，短裤和头发直接粘死）。

### 坑 4：靠形态学开运算"削细线" —— 削掉真衣服

**现象**：2 轮开运算把衬衫下摆吃掉 80px、发梢没了；3 轮连短裤上沿都掉了。
**根因**：衣摆、发梢和"多余描边"在**宽度上是同类**（4–7px），几何上分不开。
**修法**：不要用"细"作为唯一判据。改成：**远离身体核心** 且（**贴着别的部件** 或 **比本体暗 15L**）。
**记住**：颜色归属的问题在颜色层解决；几何只解决"粘在谁旁边"。

### 坑 5：那条"手臂轮廓"和衬衫同色

**现象**：衬衫件里一条细线沿手臂延伸。
**实测**：像素 RGB ≈ (203,162,124)，和衬衫本体几乎一致 —— **它根本不是深色描边**。
**修法**：只能几何剔除（见坑 4 的判据）。

### 坑 6：灰线归属"谁先扩谁拿走" → 顺序偏置

**现象**：衬衫把两条手臂的暗描边一起吞进来，导出图出现鬼影轮廓。
**根因**：按族顺序扩张，先扩的族在争夺区赢。
**修法**：用**邻域多数**（积分图 box_sum，窗口 argmax），无顺序偏置。

### 坑 7：抗锯齿混色把边界判给错误族

**现象**：手臂边缘的过渡像素（纸→橙）中间那几档是棕色，被判进衬衫。
**修法**：分类完成后加一次**邻域多数投票**（半径 1，≥3 票），把这些像素还给真正相邻的填色。

### 坑 8：小色块低于直方图阈值 → 眼睛消失

**现象**：脸盘有眼窝没眼珠。
**根因**：眼睛几十到几百像素，分散在多个 16 级桶里，每个桶都低于阈值。
**修法**：残差里再走一遍连通域，用**自身均色**重判色族（sat ≥ 0.15 且 val ≥ 0.25 才算填色）。

### 坑 9：脱离主体的孤岛 / 断掉的笔画

**现象**：衬衫件里飘着指尖轮廓；`hair` 里飘着一小段发丝。
**修法**：每件只保留主体 + "距主体 ≤3px 或面积 ≥5%" 的岛。**代价**：确实会丢几笔碎线（见已知限制）。

### 坑 10：左右命名反了

**现象**：用户一眼看出"左右腿标反"。
**根因**：我一开始按**观众视角**命名（观众左 = 部件名 left）。
**修法**：按**角色自身**命名（观众左 = 角色右），并且分界线必须是**角色重心线** —— 
这女孩站得偏左、一只手向右伸，用**画布中线**会把两条腿判到同一侧（实测发生过）。

### 坑 11：全局"描边层"是个垃圾场

**现象**：把剔除的像素收进 `outline.png`，得到的是散落的指尖/缝口，不是线稿。
**结论**：**不要做全局描边层**。真实引擎里描边烤在各自部件贴图里，部件动线才跟着动。
保持"剔除即丢弃"。

### 坑 12：输出透明度的写法

每件都从原图复制 RGBA，然后把 alpha 乘上（或按 mask 置 0）：
`alpha = original_alpha if mask else 0`。别新建透明画布再 paste 裁剪后的图 —— 会丢绝对坐标。

### 坑 13：部件必须互斥且全画布对齐

- 测试 `test_parts_keep_full_canvas_and_stay_disjoint` 盯着这两条：
  每张 PNG 尺寸 = 原图尺寸；所有部件的 mask 叠加后每像素最多 1。
- 下游摆骨点全依赖绝对坐标，所以**永远不要裁切**。

### 工程侧坑（不是算法，但同样花时间）

| 坑 | 说明 |
|---|---|
| `Set-Content -NoNewline $p $t` | PowerShell 参数位置写错会**静默不生效**（要先 `-Path`）。改代码优先用编辑工具，不要用字符串替换脚本 |
| `cd X; node y.js` 一行 | OpenClaw exec 的 preflight 会拦链式命令；拆成单条 + `workdir` |
| 大图调试 | 1M 像素的中间结果落盘看，别在终端里打印数组 |

## 五、验收方法

1. `python -m pytest -q` 全绿（拆分器相关 8 个用例）。
2. 命令输出里的 `coverage` ≥ 0.93、`mean_diff` ≤ 30 视为合格。
3. **必须目视** `preview/parts_sheet.png`：每格只有一个部件、没有飘线、没有别人家的轮廓。
4. `preview/reassembly.png` 左右对照：缺失应集中在细描边，而不是整块。

本次（girl 图 896×1184）实测：**11 个部件，coverage 0.935，mean_diff 25.24**。

## 六、已知限制

- **描边归属靠"邻域多数 + 距离"**：细线断口、少量碎线仍会出现（`hair` 右下有一段脱离发丝）。
- **衣摆/发梢会损失 10~25px**：被"描边剔除"一起带走。
- **命名是位置启发式**：按 `cy` 分带判 head/arm/leg。换姿势（例如躺下、倒立）会失效。
- **只支持"前景 + 单一纸张背景"**：渐变背景、照片、带投影的素材不在适用范围。
- **部件语义不跨图**：同一个人物换一张图，部件名可能变（数量不同就会重新编号）。

## 七、下一步

拆分只是第一步。按蓝图走：

```
split (本文) → rig（骨点草案 + bones 表）→ build（skeleton.json + atlas）→ preview
```

`parts.json` 里的 `box` / `center` 就是摆骨点的输入：骨点取部件端点，
附件 `x/y` = 部件中心 − 所属骨点，`width/height` = 部件尺寸 × 图集缩放倒数。
